\begin{abstract}
Flood-risk studies chain data acquisition, extreme-value and copula
statistics, stochastic rainfall generation, climate bias correction and
hydrological and hydraulic simulation, usually through ad-hoc scripts that
are hard to reuse and reproduce. \pyhydra{} is an open, modular Python
library that consolidates this chain into fifteen sub-modules: harmonised
access to public hydro-climatic data, statistical and copula tools,
stochastic generators, bias correction and downscaling, automation of
HEC-HMS, HEC-RAS, SFINCS and SWAT+, and uncertainty propagation, including
a pilot-based rule that decides whether an expensive solver can be emulated
within a fixed simulation budget. It is illustrated through four workflows
at three Spanish sites; external-engine outputs are archived and third-party
adoption is still to be shown. \pyhydra{} is
GPL-3.0-licensed, installable from GitHub (not yet on PyPI) and archived on
Zenodo; the companion platform HYDRA exposes its notebooks in a browser.
\end{abstract}

\section{Motivation and significance}
\label{sec:motivation}

Flood-risk assessment combines heterogeneous hydro-climatic data,
extreme-value and dependence models, scenario generation, climate bias
correction, and hydrological/hydraulic simulation. Study-specific scripts
make this chain difficult to reproduce or transfer, particularly where
resources for characterising flood hazard are limited
\citep{dibaldassarre2010}.

\pyhydra{} consolidates a line of impact-based flood-risk research into
reusable, versioned Python components. The founding Besaya study combined
geostatistical event generation and probabilistic regression to estimate
return periods directly on hydraulic impacts \citep{navas2018besaya}.
Subsequent applications covered spatial rainfall generation with NEOPRENE
\citep{diezsierra2023neoprene}, Gaussian-copula/MaxDiss flood-frequency
analysis in Madrid \citep{navas2024calle30}, climate impacts on reservoir
inflows \citep{navas2025simpce} and Andean hydropower
\citep{deljesus2020andinos}, and vine-copula design storms
\citep{urrea2026vine}. These studies repeatedly implemented overlapping
statistical and modelling components.

The contribution is an architecture that composes established methods from
source data to impact-based frequency products. Its four blocks provide
data access, climate/statistical analysis, model integration and uncertainty
quantification (UQ). Statistical components work independently of hydraulic
models, while adapters retain external engines as replaceable components:
HEC-HMS \citep{scharffenberg2016hechms}, HEC-RAS
\citep{brunner2016hecras}, SFINCS \citep{leijnse2021sfincs} and SWAT+
\citep{gassman2007swat}. Public data services remain independent sources
\citep{hersbach2020era5,huffman2020gpm,alfieri2013glofas,poggio2021soilgrids}.
The companion platform HYDRA adds browser access and a Docker environment;
it is separate from the library described in \cref{tab:metadata}.

Related frameworks address complementary tasks: CLIMADA combines hazards,
exposure and impact functions \citep{aznar2019climada}; RainyDay generates
storms by transposing remotely sensed fields \citep{wright2017rainyday};
and HydroMT/wflow supports reproducible distributed-model construction and
execution \citep{eilander2023hydromt,vanverseveld2024wflow}. \pyhydra{}
combines multivariate extremes, stochastic generation, climate correction,
model adapters and impact-frequency analysis within one workflow, using
ecosystem packages such as HydroMT-SFINCS where appropriate.

\subsection{Software architecture}
\label{sec:architecture}

\pyhydra{} is a pip-installable Python package organised into four blocks:
data sources, climate and statistics, model integration, and UQ
(\cref{fig:architecture}). Exchange formats include
\path{pandas.DataFrame}, \path{xarray.Dataset}, GeoTIFF and
\path{geopandas.GeoDataFrame}, allowing components to be replaced or
bypassed. The library contains no web infrastructure. HYDRA adds JupyterLab,
FastAPI, an Astro/nginx frontend, Docker and Azure Container Apps deployment.
\pyhydra{} incorporates GPL-v3 code and is distributed under GPL-3.0-only;
HYDRA is independently licensed under MIT.

\centering
\includegraphics[width=\linewidth]{figures/fig01_architecture.pdf}

\begin{sloppypar}
Sub-modules expose their public API through \texttt{\_\_init\_\_.py}, using
\texttt{from pyhydra.<block>.<module> import <name>}.
OpenTURNS, a core dependency, supplies Gaussian-copula fitting. Dependencies
are imported lazily, so components remain usable without unrelated heavy
packages. Four extras group optional dependencies:
\texttt{statistics} (PyMC, pyvinecopulib, lmoments3),
\texttt{geospatial} (GeoPandas, rasterio, pykrige, earthaccess,
hydromt\_sfincs), \texttt{models} (hecdss, pySWATPlus, spotpy, NEOPRENE)
and \texttt{notebooks} (seaborn, contextily, xlrd, openpyxl).
A legacy \texttt{geo} extra provides GDAL bindings; \texttt{all} covers all
five. CoSMoS\_py requires separate installation from its repository.
HYDRA's Docker Compose stack supplies extended scientific dependencies and
mounts project data from a persistent file share; GitHub Actions deploys the
stack to Azure Container Apps.
\end{sloppypar}

\subsection{Software functionalities}
\label{sec:functionalities}

\Cref{tab:modules} summarises the fifteen sub-modules. They implement
established bias-correction \citep{teutschbein2012biascorrection},
index-flood/L-moments \citep{hosking1997rfa} and copula
\citep{genest2007copulas} methods. Modularity, explicit parameters and data
conventions, standard exchange formats, documentation and notebooks support
independent use, reproducibility, interoperability and transfer.

A \texttt{pytest} suite comprises 299 tests in 19 files. GitHub Actions runs
it on Ubuntu across Python 3.9--3.12, with core and lightweight extended
dependencies including PyMC. For commit \texttt{e96fbca} (23 October 2026),
299 tests pass on Python 3.10--3.12; on 3.9, 298 pass and one PyMC/pytensor
test is skipped because the resolved stack is incompatible with NumPy.
That test is guarded by \texttt{optional\_dependency} when the stack is
unavailable or incompatible. Line coverage is 32\% (31\% on 3.9), concentrated
in statistical, modelling-adapter and UQ utilities. Data connectors and
engine automation have lower coverage and are exercised, rather than
formally verified, by pilot notebooks. See the \href{https://github.com/navass11/pyhydra/actions/runs/39978050001}{archived CI run}.

\paragraph{Reproducibility boundary}
Statistical and bias-correction examples use included or synthetic data.
Public-data downloads require service credentials and recorded queries;
model workflows also require host-installed engines and project files.
Some third-party inputs cannot be redistributed. The audit contract
(\cref{fig:reproducibility}) records sources, parameters, seeds, engine
configuration and environment; containerisation alone does not make
restricted data or external executables available.

\begin{sloppypar}
\paragraph{Uncertainty propagation and analysis}
UQ includes asymptotic, bootstrap and Bayesian extreme-value estimates;
regional posterior propagation and spatial prediction variance; and
roughness ensembles aggregated into impact statistics with outlier
screening. The \texttt{uq} layer chooses whether to emulate an expensive
solver within budget \texttt{n\_max}. A nested maximum-dissimilarity pilot,
charged to that budget, measures cross-validated emulability against a
declared emulator family. The layer then completes a reduce-and-emulate
design or falls back to direct Monte Carlo.
\texttt{StrategyDecision.margin} identifies borderline choices, while
sequential design classifies added points as improving, converged or
deteriorating.
\end{sloppypar}

\textbf{Los Corrales de Buelna (Besaya River, Cantabria).}
The founding case \citep{navas2018besaya,navas2018tfm} combines 42 years of
continuous hydrological simulation (1970--2012), 13 rain gauges,
geostatistical rainfall reconstruction, copula-generated events and
$k$-NN flood-map reconstruction ($k=6$, selected by cross-validation).
Return periods are estimated on hydraulic impacts. Simulated floods may
affect over 13\% of the population and 20\% of the town's area
\citep{navas2018tfm}.

\textbf{M-30 Manzanares (Madrid).}
The published study \citep{navas2024calle30} classified 1{,}761 events from
17 gauges using PCA and k-means. A Gaussian copula generated approximately
one million events; MaxDiss selected 625 for HEC-HMS and steady HEC-RAS 1D
(303 cross-sections). k-NN depth reconstruction and a compound Poisson
frequency model gave a 500-year depth of 7.61~m at Puente de Toledo,
0.83~m above the univariate-GEV estimate (6.78~m).

Because historical events and engine runs cannot be redistributed, the
notebooks fit \texttt{FloodEventCopula} to an archived 10{,}000-event
synthetic sample. An OpenTURNS Normal copula with zero-inflated marginals
regenerates 100{,}000 events over 84 variables, reproducing dry-gauge shares
and rank dependence (mean $|\Delta\rho|=0.011$ across 3{,}486 pairs).
MaxDiss selects 625 events in that space. Published design depths are read
from archived outputs, not recomputed (\cref{fig:m30}).

\textbf{Valencia's DANA (October 2024).}
Turís (8337X) recorded 710.8~mm on the calendar day of 29 October 2024,
during the record-breaking event documented by AEMET \citep{aemet2024dana}.
Two notebooks, obtainable with \texttt{pyhydra-get-data valencia\_dana}
without run-time AEMET credentials, fit GEV distributions with and without
the event. Point fits use MLE, L-moments and Bayesian/MCMC; regional
frequency analysis (RFA) uses nine-station index-flood standardisation with
MLE and L-moments. The estimated 100-year level rises from 218--271 to
756--1{,}241~mm, a factor of 3.5--4.6
(\cref{fig:valencia,tab:valencia}). All values are recomputed with v0.3.1.
These short annual-maximum records have an upper tail dominated by one
record. The ratios measure sensitivity to that event rather than calibrated
return levels; sensitivity to station selection is not assessed.

\section{Impact}
\label{sec:impact}

Six journal articles from the authors' group use methods consolidated in
\pyhydra{}
\citep{navas2018besaya,diezsierra2023neoprene,navas2024calle30,navas2025simpce,deljesus2020andinos,urrea2026vine}.
This track record predates the software product and supports the underlying
methods; it does not establish external software adoption.

The four workflows now share reusable components and ensemble/impact
statistics instead of independent scripts. This supports investigating how
engines propagate identical roughness ensembles and how impact-based
frequency estimates differ from univariate estimates. The former comparison
is reported separately; the latter is quantified by the published M-30
study. Applying the generic copula fitter to M-30 also exposed inappropriate
heavy-tailed marginal selection for zero-inflated rainfall. Restricted
families and zero-inflated marginals are now included in the tested API.

Zenodo archives provide citable versions of \pyhydra{}
\citep{navas2026pyhydra} and HYDRA \citep{navas2026hydrarepo}. HYDRA's
README gives a browser deployment, reachable on 24 October 2026, with the
scientific stack pre-installed.\footnote{The Azure Container Apps deployment
is ephemeral; Zenodo provides the durable scholarly records.}

\section{Conclusions}
\label{sec:conclusions}

\pyhydra{} integrates hydro-climatic data access, statistical analysis,
model automation and UQ in a modular GPL-3.0-only Python library. HYDRA adds
optional browser and container access. Four workflows demonstrate reuse
across fluvial, urban and extreme-rainfall studies. Archived M-30 design
depths and HEC-HMS/HEC-RAS results are not validation of the library, and
external adoption remains to be demonstrated.

Short records constrain extreme-value inference; RFA requires homogeneous
regions; stochastic generators do not resolve climate non-stationarity;
and emulation depends on representative designs and physical-model
validation. External-engine versions, licences and project/data availability
condition reproducibility. Future work will expand test coverage and model
adapters and document a stable public API for external contributors.
